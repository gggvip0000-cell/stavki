# Как работать с этим проектом

Владелец (Сергей) не программист, код не читает. Объяснять по шагам: где нажать, что появится.
В конце каждого ответа — что от него требуется (или «от вас сейчас ничего не нужно»).

## Важное о программе
- `main` — это то, что программа владельца ставит себе по кнопке «Обновить». В `main` кладём
  только проверенное (запуск на сохранённых ответах odds.ru, синтаксис, снимок окна).
- При каждом изменении `stavki.py` поднимать `VERSION` (формат `ГГГГ.ММ.ДД-N`), иначе кнопка
  «Обновить» не появится.
- `Stavki.bat` обновлением НЕ заменяется (cmd читает .bat по ходу выполнения). Его меняем редко
  и присылаем владельцу файлом.
- В `.bat` — ТОЛЬКО ЛАТИНИЦА, включая комментарии (Windows читает .bat не в UTF-8). Всё русское
  печатает Python.
- `.bat` НЕ собирать через printf/echo в оболочке облачной машины: там `>nul` подменяется на `>/dev/null`, и на
  Windows .bat пишет «Системе не удается найти указанный путь» и не находит Python (21.11, Razvedka_rynkov.bat).
  Писать текст файлом, переводить строки в CRLF через Python и проверять: есть `>nul`, нет `/dev/`, всё ASCII.
- Telegram: ключ бота и номер чата — в config.json (не в git); подключение — поле и кнопка в «Подробнее».
  Уведомление — только о новой ставке основного способа Б с ценой с сайта конторы.
- Окно программы обновляется само, без перезагрузки страницы — это обязательное требование.
- Пороги и способ расчёта не менять «по здравому смыслу» — только новой проверкой на данных.
- Деньги владельца — только после проверки, что коэффициенты odds.ru совпадают с конторами
  вживую, и после учёта ставок на бумаге (CLV).

## Честная цена: Pinnacle С ЕГО САЙТА (с 21.11 вечера; версия -11)
- 21.11 ~19:00 МСК Pinnacle пропал с odds.ru (разведка 20:02: ни в одном ответе, ни в футболе, ни в хоккее/баскетболе;
  снимок владельца это подтвердил). Код odds.ru-Pinnacle оставлен запасным (`pinnacle_fair`), если вернётся.
- pinnacle.com открывается у владельца через его VPN. Гостевой API сайта: `https://guest.api.arcadia.pinnacle.com/0.1`
  с заголовком `x-api-key` (ключ берётся из запросов самой страницы при запуске и сохраняется в config.json;
  если скрытое окно цены не получило — сохранённый или открытый ключ сайта `PIN_PUBLIC_KEY`). Футбол = sport 29.
  `/sports/29/leagues?all=false` (271 лига), `/leagues/{id}/matchups`, `/leagues/{id}/markets/straight`.
  Цены американские (−120 → 1.833). Основной матч: type matchup, units Regular, без parentId; угловые/карточки —
  отдельные matchup с parentId и units Corners/Bookings. Рынки: moneyline (home/draw/away), total, spread,
  team_total; period 0 — матч, 1 — первый тайм.
- Сопоставление с odds.ru — по английским названиям из адреса матча odds.ru (`/match/a-vs-b/idA-idB/`, порядок частей —
  по возрастанию номеров команд, не хозяева/гости!) и времени ±20 мин. Проверка 21.11: 48 из 48 матчей.
- Лиги опрашиваются по очереди: с матчем в ближайшие 3 ч — раз в минуту, 12 ч — раз в 3 мин, остальные — раз в 10 мин.

## Рынки (версия -17)
- Ключ рынка: (семейство, линия). Семейства: 1x2, total, ah (фора, линия = фора хозяев), tt1/tt2 (инд. тотал хозяев/гостей);
  с приставкой h1_ — первый тайм, c_ — угловые. Названия исходов — одна функция `outcome_names` для Pinnacle,
  Фонбета/PARI и таблицы pin (по ним ищется цена закрытия), подписи — `market_label`.
- Фонбет/PARI: коды пар из каталога сайта (`F_TOTALS`, `F_AH`, `F_TT1`, `F_TT2`), линия = p/100 первого кода;
  подсобытия «1-й тайм» и «угловые» (parentId) — те же коды. Карточки (желтые) не сравниваем: у Pinnacle
  «Bookings» может считаться очками, а не жёлтыми — не проверено.
- На бумагу (paper2) идут только рынки, которые считаются по счёту матча (`SETTLEABLE`: 1x2, total, ah, tt1, tt2).
  Первый тайм и угловые — только в журнал CLV (`cand`, столбец fam).
- Линии с возвратом (целые 0/±1/2/3, четвертные x.25/x.75): перевес = шанс_выигрыша·кф + шанс_возврата − 1
  (`win_push`, `true_ev`); шансы целой линии — по соседним половинным линиям Pinnacle. Нет соседних — строка
  пропускается. Так же считается CLV (`closing_fair` возвращает честную цену и CLV). Проверка — test_push18.py.
- «Шанс» (и способ В «шанс ≥55%») с версии -18 — чистый шанс выигрыша без возврата; на половинных линиях
  то же, что раньше. Порог «брать, если кф не ниже» = (1 + 5% − возврат) / шанс выигрыша.
- Запасная ветка odds.ru-Pinnacle в `values_from_rates` (если Pinnacle вернётся на odds.ru) возврат НЕ учитывает —
  перед её включением доделать.
- Событие для бумаги: исход и фора — одно событие (`EVENT_GROUP`: Ф1 −0.5 = П1). «★ лучший» в карточке — среди
  рынков бумаги, как способ Б.
- Pinnacle при перевёрнутых хозяевах: 1x2 и фора разворачиваются, tt1↔tt2. Проверка 21.11: фора хозяев 0 у
  Ньюкасл—Арсенал 17.8% при П1/(П1+П2)=18.9%.

## Источники цен (разведка 21.11.2026)
- odds.ru: `/next-api/sports/events/ru/?sport=football&status=all&date=ГГГГ-ММ-ДД&source=default` — матчи дня;
  `/next-api/coefficients/rates/ru/?sport=football&matchId=…&metricId=full_time&periodId=full_time&marketId=match_winner|total_points&source=default`
  — 15 контор, Pinnacle = id 18. Цены обычных контор на odds.ru ОТСТАЮТ (сверка 21.11: Олимп 1.76 на odds.ru
  при 1.62/1.67 на сайте) — для них только подсказка. Pinnacle на odds.ru совпал с OddsPapi.
- Фонбет и PARI — одна платформа: `<host>/events/list?lang=ru&version=…&scopeMarket=1600|2300`, изменения каждые
  ~3 с. Коды: 921/922/923 = П1/Х/П2; тоталы — пары (930,931),(940,941),(1848,1849),(1696,1697),(1727,1728),
  (1730,1731),(1733,1734),(1736,1737),(1739,1791),(1793,1794),(1796,1797),(1799,1800),(1802,1803),(1805,1806),
  линия = p/100. Футбол: segment.parentId == 1; только level 1, place 'line'.

## Ставки на бумаге (с версии 2026.11.21-8, решения владельца 21.11)
- Владелец ставит ОДНУ ставку на событие в ОДНОЙ конторе — где кф выше. Событие = матч + рынок (исход; все линии
  тотала одного матча — одно событие). Проигрыш одной ставки в нескольких конторах — один проигрыш.
- Таблица `paper2`: на каждое событие по одной ставке для каждого способа отбора (`STRATEGIES`), цены с сайта
  конторы и с odds.ru — раздельно (`src`). Записывается первая подходящая цена, дальше не меняется.
  Способы записаны заранее и на ходу не меняются: Б — перевес ≥5%, кф ≤4, лучший по «надёжности» (как в карточке,
  основной); А — то же, лучший по перевесу; В — перевес ≥3% и шанс ≥55%. Новые способы — только добавлять.
- «Надёжность» = перевес / (кф·√(p(1−p))). Расчёт 21.11 (5+ сезонов): даёт 53% выигрышей вместо 42% при том же доходе.
- Журнал `cand`: КАЖДАЯ ставка моих контор с перевесом ≥3% и кф ≤4 — CLV против последней цены Pinnacle до начала.
  Это главная проверка, есть ли перевес вживую. Когда переходить на деньги — владелец решает по ходу (без числа матчей).
- Старая таблица `paper` (каждая линия × каждая контора) пересчитана и лежит как `paper_old`.
- Связки ставок не делаем: перебор 2730 вариантов на 45 тыс. матчей — ни одной в плюсе (доход связки = сумма ног).
- Результат — по счёту матча из списка odds.ru (status completed).
